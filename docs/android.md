# 短信转发（独立 Android App）

安装包名称“短信转发”，包名 `com.kidbuddy.smsforwarder`。支持 Android 10 及以上，提供可侧载的 APK，不依赖 GMS、不收费发送短信。支持配置多个转发目的地（**飞书、企业微信、钉钉、自定义 HTTPS Webhook**）与多条独立过滤规则。

## 使用

1. 在首页进入「管理转发目的地」，点击「添加目的地」，选择平台并填写名称、HTTPS Webhook 地址和可选签名密钥：
   - **飞书**：`https://open.feishu.cn/open-apis/bot/v2/hook/...`，关键词可设为“短信转发”，启用签名校验时填写密钥。
   - **企业微信**：`https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`（无需签名密钥）。
   - **钉钉**：`https://oapi.dingtalk.com/robot/send?access_token=...`，关键词可设为“短信转发”，启用加签时填写 `SEC...` 密钥。
   - **自定义 Webhook**：任意合法 HTTPS 地址；发送 JSON `{"title":"短信转发","text":"...","timestamp":...}`，选填密钥时附带 `X-Webhook-Timestamp` 与 `X-Webhook-Signature` 请求头。
2. 在首页进入「管理转发规则」，点击「添加规则」，为规则命名、选择对应的转发目的地，并按需要设定过滤条件（可创建多条规则，例如验证码发飞书、告警发企业微信、银行通知发钉钉）。
3. 首次安装后在首页进入「权限管理」，点「授权接收短信」，并在系统弹窗中允许。若弹窗未出现，可通过页面上的应用设置入口检查短信权限。
4. 开启自动转发，阅读并确认提示。点击「发送测试消息」（支持选择单个或全部目的地）验证连通性，再用另一部手机发普通短信验证完整链路。

从旧版升级安装（`adb install -r`）时，原有的飞书机器人配置和单条过滤条件会自动迁移为「默认飞书群」和「默认规则」，原有待发队列也会继续兼容发送。

收到新短信时，App 会依次评估所有**已启用**的规则：
- 一条短信若命中多条指向**不同目的地**的规则，会分别入队投递到各个目的地；
- 一条短信若命中多条指向**同一目的地**的规则，会自动去重，只向该目的地发送一次。

自动转发默认关闭，暂停期间短信不会补发。无需默认短信应用身份，不读取历史收件箱。彩信、RCS、通知消息不支持。地址与密钥默认隐藏，仅保存在本机应用私有目录，不写日志、不参与备份。

首页显示转发开关、待发数量、短信权限、规则/目的地摘要与最近动态，并提供权限管理和队列管理入口。底部“外观”可选择浅色、深色或跟随系统。App 无需固定屏幕，可正常返回桌面，在后台等待新短信。

## 权限和后台设置

| 项目 | 用途和处理方式 |
| --- | --- |
| 接收短信（`RECEIVE_SMS`） | 监听新到的普通短信，开启自动转发前必须授权。若系统安装器未允许此权限，系统可能无法授权。 |
| 联网（`INTERNET`） | 通过 HTTPS 将消息发送到飞书，系统在安装时授予。 |
| 访问网络状态（`ACCESS_NETWORK_STATE`） | 让系统按网络条件调度发送任务并检查流量限制，系统在安装时授予。 |
| 接收开机广播（`RECEIVE_BOOT_COMPLETED`） | 在开机解锁后恢复后台发送任务，系统在安装时授予。 |

权限管理页从系统设置返回时会重新检查状态。如果锁屏后转发延迟或积压，可检查后台用电、电池优化和后台流量。小米或红米等设备的自启动状态无法通过通用 Android 接口读取，请在手机设置中找到本应用，允许自启动，并按需将省电策略设为“无限制”。这些后台设置不会阻止在 App 里打开自动转发开关。

## 哪些短信要转发

首页点击“设置转发范围”，可按短信内容、发信号码或组合条件缩小范围。按使用目的选择：

| 选择 | 保存后的效果 |
|---|---|
| 全部短信 | 不筛选，所有新短信都会转发；原有排除词和来源限制暂不生效，但配置保留。 |
| 验证码短信 | 正文同时含“验证码”和连续4～6位数字；保留已有排除词和来源限制。 |
| 验证码字样或数字 | 正文含“验证码”或有连续4～6位数字；订单编号也可能命中，保留已有排除词和来源限制。 |
| 自己设置 | 自行填写关键词、勾选数字条件，选择有一个符合即可或两项都符合。 |

页面用一句话说明设置后的转发范围，并区分“当前设置”和“修改未保存”。更换选项不会立即影响实际转发；已有规则打开时保持原样。

需要额外限制时，展开可选项：

- **不转发这些内容**：填写不想转发的文字，例如“银行”。命中其中一个就不转发，优先于正文条件。
- **只转发这些号码**：不填写表示不限来源；可填完整号码或 `106*` 这样的开头，例如 `106*` 表示106开头的号码。多项可换行或用中英文逗号分隔。

底部始终提供“试一条短信”和保存按钮。试短信会弹出本地测试框：填写号码和正文，或选择样例，即可看到“会转发／不会转发”和原因。测试使用当前表单中的设置，不保存、不发到飞书，也不存入待发队列。

确认后点击保存，返回首页查看正在使用的转发范围。保存筛选设置不会开启或关闭首页的“自动转发”开关。修改后直接返回时，会提醒是否放弃未保存的内容。

例如：选择“验证码字样或数字”，在“不转发这些内容”里填“银行”，就表示 **（含“验证码”或连续4～6位数字）且不含“银行”**。如果两项都需要，选择“验证码短信”。

连续数字兼容全角；7位及以上数字串不会截取匹配。关键词忽略字母大小写，每组最多32项，每项最多64字；号码规则最多32项，不按尾号模糊匹配。号码会去除空格、横线和括号，支持全角数字及中国手机号的 `+86`／`0086` 格式。自定义模式下，未填写的正文条件不参与判断；正文都未设置时，可仅依靠排除词或来源限制。

筛选只在新短信入队前执行，跳过的正文不保存在本 App。修改设置不会重读历史短信、删除或重新筛选已有待发消息。配置损坏时拒绝新短信入队，并提示重新保存筛选设置。

## 发送和重试

收到的分段短信合并为一条，附发件人与时间。原始 PDU 和 SIM 订阅共同生成去重指纹；只保存哈希（最多 2000 个、7 天）。短信暂存在本机 SQLite 私有目录，飞书返回 `code=0` 后删除正文。不保存已成功正文。

断网由系统 JobScheduler 等待网络后重试，指数退避，单条失败 8 次后保留队列，修复配置或网络后点击“重试待发消息”。另有 15 分钟周期恢复任务，检查待发队列是否需要重新排程；系统可能延迟运行和投递，15 分钟不是送达时限。最多积压 200 条，单条正文上限 16KB，编码转义后的完整请求不得超过 20KB，超过限制提示失败；不会无限消耗存储。较长短信需要在原短信 App 查看。状态只显示最近事件，不显示短信正文。到达上限时后续短信无法转发，应及时处理队列。

暂停会取消后台任务并停止继续发送，已经到达飞书的在途请求不能撤回。网络请求成功但回执丢失、进程在确认前退出时，重试可能产生重复消息（Webhook 不支持接收端幂等键），不承诺恰好一次送达。关机重启后，解锁手机后恢复任务；Android/MIUI 省电限制可能延迟后台发送。强行停止 App 后需重新打开。

修改接收群前先暂停并清空队列，避免积压短信误发往新群。清空后不会重读原短信补发。App 配置不是端到端加密，系统 root 或设备解锁权限可能访问本地数据。

## 构建

按[开发指南](development.md)配置环境后，在项目根目录运行。

```bash
cd android
./gradlew testDebugUnitTest assembleDebug lintDebug
```

APK：`android/app/build/outputs/apk/debug/app-debug.apk`。

协议依据：[飞书自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot?lang=zh-CN)、[Android SMS 广播](https://developer.android.com/reference/android/provider/Telephony.Sms.Intents)。本工程仅为自用侧载；应用商店短信权限另有上架限制。
